# 模拟交易

模拟交易让你将一个已完成回测的策略部署到虚拟账户中运行，每日自动推进，真实感受策略在"实盘"中的表现。

## 与回测的区别

| 维度 | 回测 | 模拟交易 |
|------|------|----------|
| **运行方式** | 一次性跑完整个区间 | 每天收盘后推进一天 |
| **成交逻辑** | 相同（next_open/current_close） | 相同 |
| **时间感** | 瞬时完成 | 跟随真实日期逐日前进 |
| **可对比性** | - | 模拟净值可与回测曲线直接对比（同构引擎保证） |
| **调度** | 手动触发 | APScheduler 每个交易日 17:00 自动执行 |

## 使用步骤

### 1. 创建模拟账户

- 进入 **模拟** 页面
- 点击 **新建**，选择已保存的策略，设置初始资金
- 创建后账户状态为 `stopped`

### 2. 启动

- 点击 **启动**，账户状态变为 `running`
- 调度器会在下一个交易日 17:00 自动推进

### 3. 监控

- **净值曲线**：每天生成一个净值快照，与回测曲线叠加对比
- **持仓表**：当前持仓明细（标的、数量、成本、市值）
- **订单流**：所有历史订单，按状态显示 pending/filled/rejected
- **策略日志**：`ctx.log()` 输出的内容

### 4. 暂停/停止

- 点击 **暂停** 可随时停止自动推进
- 暂停后可以重新启动

## 调度机制

- 每天 17:00（收盘后）调度器扫描所有 `running` 账户
- 对每个账户，获取最新交易日数据，执行一次 `on_bar`
- 新的订单（如果不是当日成交模式）会挂起到下一个交易日
- 净值、持仓、订单都会持久化到数据库

## 注意事项

- 模拟交易的成交假设与回测一致（`next_open` → 次日开盘价成交）
- 因此模拟交易的净值曲线应该与回测中对应时间段的曲线高度一致
- 如果出现偏差，可能是数据更新延迟或调度时间点的差异
- 资金不足、停牌等异常情况会被记录在订单状态中
